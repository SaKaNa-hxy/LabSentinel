## 裁剪与标注原则

- 仅从冻结的实际 `train.txt` 选取，不按原图物理子目录判断所属集合。
- 每张图每种衣服类别选最大且尺寸足够的衣服框作为主要裁剪目标，保留肩部及头部上下文，截去下方约 20%–45% 的目标衣服高度；同一张裁剪图中，同一件衣服不额外增加第二个上半身框。
- 其他 12 类目标统一进行坐标平移、截断和重新归一化。画面外的框移除；可见宽高低于 3 像素的边缘碎片不作为可靠目标保留。
- 进食／饮水框须保留至少 98% 面积；其他 PPE 框至少 65%；衣服框至少 40%。遇到不满足条件的可见框时，跳过该裁剪方案，避免直接删除仍明显可见的目标。比例是本次保守几何筛选规则，不代表语义一定正确。
- 共 849 个主要目标候选因目标过小、裁剪不足或其他目标被严重截断而跳过；另有 158 个合格的普通衣服候选为保持主要目标数量一致而未采用。
- 新增图片以原分辨率裁剪，JPEG quality=95，不预先缩放。所有裁剪继承原训练图片的文件名来源组。

## 核验范围

全部 3,996 张裁剪图通过解码、边界、类别、重复框与独立坐标重算检查。全部 11,213 张原图／新增图和 11,213 份标签的哈希通过核验；父数据集原图、标签及元数据与生成前一致，验证和测试清单不变。实际采集来源仍未通过采集记录认证，文件名分组无交集不等于真实来源已认证独立。

已按固定随机种子抽查 64 张（两种主要衣服类别各 32 张），未发现明显衣服类别或裁剪范围错误。该抽查不代表全量 12 类语义经过人工认证，原有动作／PPE 标注的语义问题可能被继承。具体证据：

- `crop_manifest.json`：每张裁剪的来源、原图哈希、裁剪坐标、主要目标及输出哈希。
- `parent_manifest.json`：父数据集文件与版本记录。
- `image_manifest.json`、`label_manifest.json`：全量训练、验证、测试文件哈希。
- `verification.json`：全量独立核验及逐类计数。
- `visual_spot_check.json`：64 张抽查范围与编号。

## 使用

检查新数据版本，不启动训练：

```powershell
Set-Location C:\Users\HXY\Desktop\Design
.\.venv\Scripts\python.exe -B scripts/train.py --data datasets/laboratory_safety_upperbody_20261028/data.yaml --check-data
```

需要训练时，明确指定这个数据配置：

```powershell
.\.venv\Scripts\python.exe -B scripts/train.py --data datasets/laboratory_safety_upperbody_20261028/data.yaml --name laboratory_safety_upperbody_20261028 --epochs 100 --patience 20 --batch 8 --device 0
```

这会开始一个新训练运行，用验证集选模型，不自动评估测试集或部署。该数据版本已于 2026-10-28 完成一次训练（59 轮），最佳权重经测试集评估后已部署，SHA-256 前缀为 `0f0ad72e2954`。重复执行上述命令会开始新的运行，不是继续已完成的训练。

重建时用 `scripts/crop_upperbody_dataset.py --output datasets/<新的目录名>`，再运行 `scripts/verify_upperbody_dataset.py datasets/<新的目录名>`。构建脚本依赖父数据集及原训练解码核验记录 `runs/laboratory_safety_corrected/recovery_20261027/image_decode_validation.json`；拒绝覆盖已有输出目录。

本次单次训练测试结果为 mAP50=0.7582、mAP50–95=0.5264，相比替换前模型分别增加约 3.60、2.42 个百分点。裁剪增强可以增加原有场景中的半身视图，不能增加新的衣服款式、人物和背景；此前用户诊断图片仍有衣服类别冲突，不能据此认为现场误判已完全解决。
